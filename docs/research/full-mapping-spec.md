# Complete weather mapping and BYD Weather widget

User request: map all icons and every condition/data attribute, implement, trace, test, then spec/quality review, codebase review, and original-request review using Matt Pocock skills. User chose an additional BYD Weather widget because the original firmware ignores hourly night flags. Existing authorization preserves release version 1.1.1, version code 3, and the provided signing identity.

The forecast adapter remains the shared source of weather. All 29 documented Open-Meteo WMO conditions map to verified BYD condition IDs, preserving intensity, freezing precipitation and hail in readable descriptions. Unknown or fractional condition codes reject an update before provider writes. Each current/hourly condition keeps its source WMO code and Boolean day flag. Daily day and night conditions use matching hourly samples; future daily icons use the day condition, independent of current time.

The added Android AppWidgetProvider reads the last successfully fetched/validated payload. It displays cleaned district/city, current conditions, current measured/forecast metrics with units, seven upcoming hours with independent night flags, and seven daily forecasts. Sunrise/sunset markers retain their own meaning. Tapping opens BYD Weather. There is no second location collector or fetch loop. Adding the widget and viewing forecasts works even on hosts without the stock BYD content provider; provider synchronization remains separately reported.

Verified host constraint: the supplied stock launcher both filters its picker and removes non-allowlisted providers during workspace loading; it has no pin-widget handler. Our new provider is not on that fixed list. Therefore the same accurate renderer is also displayed inside BYD Weather, accessible from its launcher icon. The new home-screen widget is for compatible hosts; this release does not claim to repair the stock widget's mixed-hour icons or alter the stock launcher's allowlist. The Add Widget button uses the supported Android pin API when available, and otherwise explains the forecast/compatible-host path.

Forecast timestamps use the forecast location's IANA time zone, including source offsets and midnight transitions. The widget shows the data release time and an explicit stale label after an hour; unavailable data displays a meaningful empty state. It does not replace valid cached weather with malformed payloads. Views have readable contrast and icon content descriptions; widget size can expand horizontally/vertically.

Every field in the extracted native DTO inventory receives an explicit source/disposition. Populate native fields only with verified semantics and units. Preserve additional useful Open-Meteo metrics in an adapter-owned extension consumed by our widget, including hourly/daily precipitation and snow amounts. Do not invent official warning events, radar, native administrative identifiers, unknown native units or unavailable model values. European AQI must be identified as European AQI and must not trigger the native Chinese-scale pollution labels. Missing air quality must not fail weather updates.

Public test boundaries: already approved WeatherMapping.toBydJson and isComplete. For the widget, Android AppWidgetProvider.onUpdate and resulting RemoteViews are proposed separately to the user. Regression expectations come from official WMO descriptions, original firmware IDs/methods, known timestamps and observed displayed views.

Trace provider output through the original native DTO/icon methods; separately trace our actual public widget callback for mixed day/night hours. Native global-night behavior remains a firmware limitation and is not represented as repaired. Physical-car launcher support and screenshots remain device checks rather than claimed cloud validation.

Implementation sequence: complete conditions/types and validation; add widget/public-view tests; connect last-good cache and refresh; fill verified metadata and useful source metrics; native/widget trace and full test suite; independent spec/quality reports; module/codebase report; original-request report; CI lint/release build; verify original-certificate signing and deliver APK 1.1.1.
