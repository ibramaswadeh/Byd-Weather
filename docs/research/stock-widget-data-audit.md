# Open-Meteo coverage of the original stock weather widget

Research date: 2026-10-02. Scope: the user's supplied DiLink 3.0 firmware and its original **WeatherData 2.9.5.250616/code 60**, SHA-256 `f585062b2b393e3a87019da3b40c2daa089e60ddacdfab189c22c67f2279281a`. This note audits the stock card, the popup opened by that card, their hourly/daily renderers, and **all usable declared JSON attributes**, including attributes the stock UI does not display. It does not treat the removed application-owned widget or `data.openMeteo` as stock functionality. [1–5]

**Finding:** every visible meteorological attribute with a verified Open-Meteo mapping is already supplied. The stock popup's air-quality category remains intentionally unknown because its pollution categories have no verified conversion from the selected European AQI. Many other native DTO properties can bind JSON, but have no stock-display read site; some also have unresolved units or native semantics. Fetching every Open-Meteo variable cannot create more stock UI fields. **Zero additional safe weather-display mappings were found; one optional native source-link metadata field was completed.** [1–8]

Audited stock-only working-tree snapshot: parent commit `9097ec54eb36764904d33b744c46e97e3b501d79`; mapper SHA-256 `d8c2844da1146624e5adf4f4d03a60372a066a7d96a9ab3691cbad121433866d`; runtime SHA-256 `9e56a2913a54a8a150d4a99bb5eae0235860727a6f0618d95d3993ccc93f2b38`. At this snapshot the owned widget/renderer/cache, `data.openMeteo` namespace and undeclared hourly amount are removed. Forecast query contains **13 current, 9 hourly and 12 daily variables**; AQ query contains **3 current and 1 hourly variable**. All retained native mappings remain. [6]

## What “settable” means in this firmware

`WeatherQueryUtil.queryWeatherBean` reads the first provider row's `name` and deserializes it into `com.byd.weatherlibrary.WeatherInfoBean` using ordinary Gson. Exact declared names/types establish binding; a getter/setter alone does not establish units or a visible feature. The service separately uses `com.byd.weatherdata.WeatherBean`. The library DTO has hourly data but **no `aqi`, `aqidays`, `radar`, `liveInfos`, `weatherDesc` or `mobilelink` at the data-object level**; those are service properties. Unknown JSON properties are skipped. The complete declaration inventory remains [371 declarations, 29 DTO classes, 211 unique JSON paths](native-field-coverage.json); duplicated library/service fields are retained there. [1], [2], [9]

In the tables, “mapped” means currently populated by the adapter, not necessarily rendered. An upstream/emitted unit is stated separately from native evidence. An unrendered native field's unit is **not proven merely by the adapter's chosen unit**. Native timestamps are boxed `Long`; temperature and most measured native values are boxed `Integer`. Optional source nulls must not become fabricated measurements. [1], [2], [6–8]

## Source measures removed from the stock-only request

The retained official forecast response has 384 hourly entries, 16 dates, `timezone=Asia/Amman`, offset10800, and explicit source units. Its acceptance proves upstream availability; it does not prove a native use. Current `visibility` and `uv_index` must remain: both are valid source variables and populate visible stock metrics. All currently used period sampling requires the complete source hourly series, not just the48 published native hours. [6–8], [13]

| Candidate source variable(s) | Available meaning/unit | Verified native disposition after removing `data.openMeteo` |
| --- | --- | --- |
| Hourly `rain`, `showers`, `snowfall`, **`precipitation`** | Preceding-hour liquid amounts mm; snowfall physical depth cm. | No amount field at all in native hourly DTO (its exact nine fields are ID/date/day flag/probability/temp/wind). Period native amounts have unresolved units/interval; no safe new mapping. Remove hourly query/output amount rather than claim it renders. |
| Hourly `apparent_temperature`, `pressure_msl`, `visibility`, `uv_index`, `dew_point_2m` | °C, hPa, m, index, °C. | No native hourly targets. Current and daily apparent extrema have their own already requested source fields. Dew point has no native DTO field anywhere. Safe to remove these hourly queries. |
| Daily `pressure_msl_mean`, `visibility_min` | Daily mean hPa, minimum m. | Declared daily Integer pressure/visibility exist, but their native unit and aggregation are unverified; omitted. Safe to stop requesting the otherwise unused values. |
| Daily `precipitation_sum`, `rain_sum`, `showers_sum`, `snowfall_sum` | Full local-day liquid sums mm; snowfall depth sum cm. | No verified full-day amount target; cannot copy a whole-day sum into both day/night period fields. Safe to remove queries. |
| Daily `precipitation_probability_max` | Maximum hourly probability %, not period representative probability. | Existing period `precProb` reads representative hourly probability; hourly `rainprobability` has its own value. No additional native max-probability target. Safe to remove query. |
| Daily `precipitation_hours`, `sunshine_duration` | Wet hours h; WMO-defined sunshine seconds. | No native DTO target. Do not substitute sunshine duration for astronomical sunrise/sunset. Safe to remove queries. |
| Daily `wind_gusts_10m_max` | Maximum gust km/h over the local day. | Current gust and period representative gust already have their own sources. Whole-day maximum cannot silently replace the period representative force. No additional daily gust target. Safe to remove query. |
| Additional unrequested API families: cloud layers, soil, upper-air, radiation, evapotranspiration, snow depth, wave/marine values | Provider-specific weather variables and units. | No corresponding verified native DTO/UI target in this firmware. All listed unused hourly/daily query variables were removed in the audited stock-only snapshot. `hourly.relative_humidity_2m`, `cloud_cover`, `wind_gusts_10m`, `precipitation_probability`, sustained wind/direction, conditions, times and `is_day` remain: they feed existing declared period/hourly mappings. Daily `apparent_temperature_max/min` and `moonrise/moonset` remain: they feed declared native properties even though those are not displayed by this stock popup. Current source fields, ordinary daily min/max/WMO/solar/UV/max sustained wind/dominant direction, and current/forecast AQ queries continue serving retained mappings. [6]

## Evidence and limits

This was static primary-artifact/source research. No new BigDataCloud request, build, firmware modification, APK installation or car UI execution was performed. Native non-accessor usage searches were bounded to the extracted `com.byd.weatherdata`/`weatherlibrary` sources and cross-checked with the existing original-DEX declaration inventory. The conclusion applies to this APK's inspected card/popup/adapter consumers, not to unknown newer firmware or unrelated installed apps. The native global hourly/daily night limitation remains after removing the owned widget. [1–5], [9]
